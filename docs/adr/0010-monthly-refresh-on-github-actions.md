# ADR-0010: Monthly data refresh on GitHub Actions

- Status: accepted
- Date: 2026-11-04

## Context

Until Phase 9 the website data was refreshed by hand: run the pipeline on the
developer's laptop, export, create a GitHub Release, start the Pages workflow. SERCOP
regenerates its monthly files every night (ADR-0001), so the website gets old unless
someone remembers. The project has no budget.

Options considered:

- **GitHub Actions, scheduled.** Free for public repositories, runs even when the laptop
  is off, and every run leaves a public log. Each run starts on an empty machine.
- **A scheduled task on the laptop** (Windows Task Scheduler + WSL). Free, keeps the
  downloaded files, but only runs if the laptop is on, and `gh` fails on networks whose
  firewall intercepts TLS.
- **A paid server or cloud scheduler.** Not needed and costs money.

## Decision

1. `.github/workflows/refresh.yml` runs on day 3 of every month (and by hand from the
   Actions tab). It downloads the **last 24 complete months** (the current month is left
   out until it ends), runs `dbt build` with every data test and the privacy test, and
   runs `lupa export-public` with its privacy guard.
2. **Full download every run.** The machine is empty each time. GitHub's cache would not
   help: entries unused for 7 days are deleted, and the job runs once a month. This is
   also the periodic full refresh that ADR-0001 left open.
3. **A safety brake before publishing:** `lupa check-release` compares the new export with
   the current data release. It stops if a dataset is missing or empty, or if `processes`
   fell by more than 20% (moving the window changes it by a few percent). The comparison
   table appears on the run page. A failed run publishes nothing, the website keeps the
   old data, and GitHub emails the owner.
4. **The pseudonym key is a GitHub secret** (`LUPA_PSEUDONYM_KEY`), the same value as the
   local `.env`, so "Persona #abc123" stays the same person across releases. Secrets are
   masked in logs and are not given to workflows from forks.
5. A manual run does not publish unless "publish" is ticked, so the robot can be tested
   safely. The scheduled run publishes with `scripts/publish_data.sh`, the same script used
   by hand, which starts the Pages workflow.

## Consequences

- The website updates itself every month at no cost; each run is logged.
- A run takes longer (24 downloads from a slow server); the job has a 3-hour limit.
- If SERCOP blocks or slows GitHub's servers, the run fails and the laptop remains the
  fallback (same commands, by hand).
- GitHub disables scheduled workflows after 60 days without activity in the repository;
  it emails before that, and one click (or one commit) turns it back on.
- The AI gallery and the evaluation are not regenerated by the robot: they need the local
  model, so they are refreshed by hand when needed.
